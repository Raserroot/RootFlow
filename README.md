# RootFlow

> **Android Root 脚本宿主** —— 监听系统事件，把它们投递给你的常驻脚本，
> 实时打屏输出，脚本反复崩时熔断保命。

## 它是什么

RootFlow 是一个**自己的业务规则为零**的脚本宿主。它只做四件事：

```
监听系统事件  →  投给常驻脚本  →  把脚本输出实时打屏  →  出事时熔断保命
```

你的工作只有两件：**写脚本**，以及决定它**什么时候跑**。

它**不是**：

- 不是自动化 App（没有"如果…就…"的规则引擎，规则由你用 shell 写）
- 不是 root 管理器（它依赖你已经 root，不自带提权）
- 不是脚本市场（不联网、不下载任何脚本）

## 功能

### 1. 脚本：写什么就跑什么

- **纯 `/system/bin/sh`**，以 **root 身份**执行，工作目录是该脚本自己的目录
- 正文存在文件里（`/data/local/tmp/rootflow/scripts/<id>/main.sh`），
  数据库只存**内容摘要** —— 打开编辑器时会校验，手改文件会被拒绝并提示
- 两条**运行方式**：
  - **单次**：服务启动时跑一遍就结束（也有超时保护，默认 60 秒）
  - **常驻**：服务一起来就跑，**退出/被杀自动拉起**（退避 1s → 2s → 4s → 8s，封顶 30s）；
    连续快速崩 5 次**只停掉它自己**，不牵连全局

### 2. 事件 = 通知（不是启动理由）

这是本项目与常见"触发器"设计的**关键区别**：

- 事件发生时，宿主把它**投递**给**正在常驻运行**的那个脚本，**由脚本自己决定要不要理它**
- 因此 **单次脚本收不到任何事件**；"勾了事件"也**不会**让脚本启动
- 投递走**命名管道**（FIFO），路径在环境变量 `ROOTFLOW_EVENT_FIFO` 里：

  ```sh
  #!/system/bin/sh
  while true; do
    if read -r ev < "$ROOTFLOW_EVENT_FIFO"; then
      echo "收到事件：$ev"      # 形如  boot   或   wifi_changed 家里WiFi
    fi
  done
  ```

- 支持 13 个系统事件（开机 / 亮屏 / 熄屏 / 解锁 / 前台应用 / 退到后台 /
  定时 / 间隔 / 低电量 / 电量恢复 / 接电源 / 断电源 / WiFi 变化）
- 投不出去的事件**直接丢弃**（不排队、不补发）—— 事件是通知，不是队列

### 3. 总开关（全局闸门）

主页最上面那张卡。**关闭时任何脚本都不会启动**，正在跑的常驻脚本会被终止。

它**不会**动你的配置：不会把脚本的「启用」关掉，也不会清空你勾的事件 ——
只是"现在不跑"，配置原样保留。

### 4. 事件源按需启停

7 个事件源里，只有"**你的某个脚本勾了它产出的某个事件**"的那些才会启动
（省掉常驻广播接收器与轮询）。关掉总开关时全部停止 ——
只有 `power` / `battery` 例外（它们由系统按清单实例化，应用无法在运行期停掉）。

### 5. 安全熔断（保命机制）

- **触发**：脚本超时 / 同一脚本 60 秒内连崩 3 次 / 10 分钟内累计失败 20 次 / 手动
- **动作**：写 `safemode.flag` → 杀掉所有在跑的脚本 → **拦下后续事件**（内存级）→
  发高优先级通知 → 写 `safemode.log`
- **它不改你的数据**：不碰脚本的启用位，也不碰你的订阅（这一点在 UI 文案里被专门修正过）
- **退出**：设置页一键退出，或 `su -c "rm -f /data/local/tmp/rootflow/safemode.flag"` 后重启 App
- 另有 **bootloop 兜底**：60 秒内连开 3 次会被判成异常启动

### 6. 日志与可判读性

- 运行输出实时打屏（`OUT` / `ERR` / `SYS` 三档过滤，超长有丢弃计数，不静默丢）
- 宿主所有关键动作都打结构化日志（`MASTER_SWITCH_*` / `DAEMON_*` / `EVENT_*` /
  `SAFEMODE_*` / `SCRIPTS_SAVE ok` …），**为真机 `findstr` 判读而设计**
- 脚本列表里那颗 ⓘ 会列出"它为什么没跑"的**完整判定链**
  （安全模式 / 总开关 / 脚本启用 / 崩溃重试 / 前台服务 / 运行方式）

### 7. 技术栈

Kotlin 2.0 / Coroutines / Flow · Jetpack Compose + Material3 · Hilt · Room ·
DataStore · libsu（唯一 root 通道）· Haze（毛玻璃）。
全程**纯 JVM 单元测试**（1006 条），不依赖 `androidTest` / Robolectric。

## 安全声明（先读这个）

RootFlow 要求 **root 权限**，而它的功能就是**以 root 身份执行你写的任意 shell 脚本**。
这不是"可能存在风险"—— 这就是它的工作原理。因此：

1. **你写什么，它就以 root 跑什么。** 一条 `rm -rf /` 会被忠实地执行，
   宿主不会拦、也拦不住。**在真机上试脚本之前，先在你能接受后果的地方试。**

2. **不要直接运行网上抄来的脚本。** 以 root 运行的脚本能读写整个系统分区、
   能装持久化后门、能改系统设置、能读走你的任何应用数据。
   这个仓库的作者**不会**为任何第三方脚本负责，也不会替你审。

3. **不要指望沙箱。** 本项目**没有**任何沙箱、权限降级或系统调用过滤。
   脚本与你自己在 `su` shell 里敲命令的权限**完全一致**。

4. **熔断不是安全边界。** 它是为"脚本反复崩"设计的健康机制，
   **不是**用来限制脚本行为的。它拦不住任何恶意或有破坏性意图的脚本。

5. **持久化路径是共享的。** 所有脚本都住在 `/data/local/tmp/rootflow/` 下。
   一个脚本可以直接改另一个脚本的正文文件、删掉运行记录、或伪造日志。

6. **Root 本身会削弱系统安全。** 使用本项目意味着你的设备已经（或将要）
   处于 root 状态，这通常同时意味着：OTA 更新可能失败、部分银行/支付类 App 会拒绝运行、
   系统完整性校验失效、保修状态改变。这些**不是 RootFlow 造成的**，但你会遇到。

7. **请只在你自己拥有的设备上使用。** 在他人设备上安装 root 级脚本宿主，
   在多数司法辖区属于未经授权的计算机访问。

## 构建与运行

**要求**：JDK 21 · Android SDK（compileSdk 见 `app/build.gradle.kts`）· 一台已 root 的设备

```bash
# 单元测试（纯 JVM，1006 条，约 30 秒）
./gradlew :app:testDebugUnitTest

# lint（ktlint）
./gradlew :app:ktlintCheck

# 出包
./gradlew :app:assembleDebug      # 调试包
./gradlew :app:assembleRelease    # 正式包（需要你自己的签名配置）
```

**签名**：release 构建需要 `keystore.properties`（已在 `.gitignore` 中，
**本仓库不含任何签名材料**）。没有它时用 debug 包即可。

**安装后的最小流程**：

1. 授予 root（首次运行 Root 管理器会弹窗）
2. 设置页 → 关于 → 逐项授予**通知** / **使用情况访问** / **电池优化白名单**
3. 写脚本 → 选运行方式 → 勾事件 → 打开主页的**总开关**

**注意**：服务**不是开机自启** —— 每次重启后要手动打开一次 App
（本机 ColorOS 会在分发阶段拦截系统开机广播，宿主用"App 启动时补发"绕过它）。

## 真机验证状态（诚实清单）

开发与验证环境：**OnePlus 8 / Android 15 (API 35) / APatch / SELinux Enforcing**。

**已验证**（每条都有真机日志证据）：

- 总开关四条不变量：关闭即全停（含豁免脚本）、拨动开关不改用户数据、
  关闭终止在跑的常驻脚本、打开立刻启动常驻脚本
- 事件源按需启停（关闸 + 无订阅 ⇒ 只剩 `power`/`battery` 两个）
- 数据迁移 v1 → v2（26 项逐条核对，旧表改名备份不删）
- 熔断六步、bootloop 兜底、安全模式恢复
- 前台服务生命周期、通知栏文案

**未验证 —— 请不要当成"已验过"**：

1. **脚本侧真的 `read` 到事件**：宿主侧的投递路径验证过
   （`EVENT_DELIVERED` / `EVENT_NOT_RUNNING` / `EVENT_NO_READER` 都有真机日志），
   但"脚本里 `read` 成功"这一步**没在真机上跑通**
   （开发设备只有中文输入法，正文无法经 adb 注入）
2. **`runMillis`（存活时长）修复**：机制由单测以虚拟时间精确覆盖，**未单独做真机验证**
3. **`boot` 事件的完整投递**：宿主会给它 6 秒重试窗口，但真机上没拿到
   `EVENT_BOOT_DELIVERED`（测试脚本活 200ms、短于重试间隔）
4. **`always_run` chip**：仍是 UI 入口但已无实际作用（常驻与否现由「运行方式」决定），
   是否移除尚未决定
